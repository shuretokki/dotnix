SDN enforces a strict separation between **internal implementation** and **user configuration**. This architecture ensures that you can customize your system without accidentally breaking the core logic.

## Repository Layout

The repository is organized into three primary high-level directories:

::card-group
  :::card
  ---
  icon: i-lucide-settings
  title: cfg/
  ---
  **User Configuration**. This is where you spend 90% of your time. Identity, themes, secrets, and per-machine hardware settings.
  :::

  :::card
  ---
  icon: i-lucide-code-2
  title: src/
  ---
  **Internal Logic**. The engine of SDN. Contains the modular library, custom packages, and helper functions.
  :::
::

## Detailed Tree

```bash [Directory Structure]
sdn/
├── cfg/                          # User-facing configuration
│   ├── identity.nix              # User identity (name, locale, timezone)
│   ├── theme.nix                 # Theme selection + overrides
│   ├── hosts/                    # Per-machine configurations
│   ├── users/                    # Per-user NixOS/Home Manager configs
│   ├── hyprland/                 # Custom keybinds and window rules
│   └── secrets/                  # Encrypted secrets via SOPS
│
├── src/                          # System Implementation
│   ├── lib/                      # The 4-Layer Library
│   │   ├── core/                 # Layer 1: System Foundations
│   │   ├── display/              # Layer 2: Desktop Environment
│   │   ├── home/                 # Layer 3: Apps and User Space
│   │   └── profiles/             # Layer 4: System Archetypes
│   ├── pkg/                      # Custom packages
│   ├── util/                     # Nix helper functions
│   └── flake/                    # Modular flake outputs
│
├── flake.nix                     # Orchestration entry point
└── flake.lock                    # Dependency lockfile
```

## The 4-Layer Library

The heart of the system is the modular library `src/lib/`, which is divided into four logical layers to ensure clean dependency management.

### `core/` layer
Foundational system services that require root privileges and have no graphical dependency.
- **system**: Bootloader, locale, and early-stage validations.
- **hardware**: GPU drivers, audio (PipeWire), and peripheral support.
- **network**: NetworkManager, VPNs, and Encrypted DNS.
- **security**: Firewall rules and SOPS-Nix integration.

### `display/` layer
The visual stack and desktop environment. This layer depends on `core`.
- **compositor**: Hyprland configuration and session logic.
- **bar**: Waybar status bar and module definitions.
- **stylix.nix**: The central bridge between your theme selection and system-wide styles.
- **login**: The SDDM display manager and greeters.

### `home/` layer
User-specific application configuration managed via Home Manager. This layer is independent of system state.
- **apps/cli**: Shell (Zsh/Fish), Starship, and terminal utilities.
- **apps/desktop**: Browsers, media players, and communication tools.
- **bundlers**: Groupings of apps for easy enabling (e.g., `bundle.dev`).

### `profiles/` layer
High-level "system types" that bundle configurations together.
- **desktop**: A full-featured workstation profile (Core + Display + Home).
- **laptop**: Optimized for battery life and mobile networking.
- **server**: A headless profile for backend services.
